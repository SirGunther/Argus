## Review Summary

All four corrective-revalidation objectives passed. The focused Phase 7 fixes preserve active editing identity and text, highlight exact provenance ranges, present optional classification separately from availability, and retain the accepted populated layout. The newly observed movement of an active editor as a pane fills is preserved as a separate deferred Phase 7A bug rather than changing these completed outcomes. A possible user-controlled classification toggle is a future product decision under `UI-002`, not a D3 defect. Phase 8 may proceed with the browser/Node host accepted for the POC.

### D1: Confirm Active Editing Survives Incoming Projections

Files: [app.js](../../app.js), [UI state](../../ui/ui-state.mjs), [demo state](../../ui/demo-state.mjs), [focused regression](../../tests/phase7-ui-revalidation-fixes.test.mjs)

#### Problem

- **Current Behavior(s):** Before correction, rendering an incoming projection rebuilt the list and interrupted the user's active editor.
- **Expected Behavior(s):** A finalized transcript or logged-item editor retains its DOM identity, focus, caret or selection, and unsaved text while other rows arrive.



#### Requirement(s)

- Reconcile rows by stable owner-provided identity without replacing or overwriting the active editor.
- Continue receiving new projections and preserve owner-routed optimistic edit submission.



#### Solution(s)

- Phase 7 now reconciles keyed rows and preserves the active editor while updating other rows through the existing governed projection path.



#### Validation Details

- [x] Start the POC with `npm.cmd run demo:ui`, open `http://127.0.0.1:4173`, and select Record.
- [x] Begin editing a finalized transcript row and place the caret or select text within the unsaved change.

- [x] Submit the edit and confirm the accepted revision appears on the same stable row without creating a duplicate.

### D2: Confirm Complete Provenance Range Highlighting

Files: [app.js](../../app.js), [styles.css](../../styles.css), [UI state](../../ui/ui-state.mjs), [focused regression](../../tests/phase7-ui-revalidation-fixes.test.mjs)

#### Problem

- **Current Behavior(s):** Before correction, selecting provenance scrolled to its first transcript row but did not make the complete referenced range sufficiently distinct.
- **Expected Behavior(s):** Every row in the exact governed source range receives a persistent, subtle light-yellow highlight while unrelated rows remain unhighlighted.



#### Requirement(s)

- Use only the first and last segment identities supplied by the governed logged-item projection.
- Scroll to the first contributing row, highlight the complete inclusive range, and predictably replace the prior range when another source is selected.



#### Solution(s)

- Phase 7 now resolves the inclusive governed segment range, applies persistent presentation-only highlighting to every contributing row, and replaces or clears earlier highlights.



#### Validation Details

- [x] Select a logged item's source range and confirm the transcript scrolls to its first contributing row.
- [x] Confirm every row from the displayed first segment through the displayed last segment has a visible light-yellow treatment.
- [x] Confirm adjacent unrelated transcript rows are not highlighted.
- [x] Select a different logged-item source range and confirm the previous range is replaced by the new exact range.
- [x] Confirm the highlight is clear without obscuring text, selection, editing, or review indicators.

### D3: Confirm Optional Classification Is Clearly Visible

Files: [app.js](../../app.js), [styles.css](../../styles.css), [UI state](../../ui/ui-state.mjs), [demo state](../../ui/demo-state.mjs), [focused regression](../../tests/phase7-ui-revalidation-fixes.test.mjs)

#### Problem

- **Current Behavior(s):** Before correction, classification behavior was not apparent in the deterministic demo.
- **Expected Behavior(s):** A suggestion is visibly labeled optional and non-authoritative, while unavailable or degraded classification is independently visible and never blocks logged-item use or editing.



#### Requirement(s)

- Keep suggested classification separate from authoritative logged-item text and owner-routed edits.
- Present suggestion state independently from current classification-service availability.
- Preserve logged-item editing when classification is unavailable or degraded.



#### Solution(s)

- The deterministic demo now includes one optional observation suggestion, labels its non-authoritative role, and displays independent available, degraded, or unavailable classification presentation without changing logged-item ownership.



#### Validation Details

- [x] Confirm the first seeded logged item displays an optional observation suggestion labeled non-authoritative.

- [x] Confirm the footer reports classification availability independently from transcript, logged-item, session, clipboard, folder, and bridge status.
- [x] Edit a logged item with a suggestion and confirm the suggestion does not alter or override the submitted text.

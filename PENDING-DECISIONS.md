# Argus Pending Decisions

This is the central queue for choices Argus intentionally postpones. It covers product behavior, packages, SDKs, providers, transport, storage, security, and acceptance thresholds. Accepted decisions belong in the code-adjacent architecture records and canonical decision register; this file contains only unresolved or deferred choices.

## How to use this register

1. Add a row before an unresolved choice is hidden inside implementation.
2. Continue with the documented safe default only while the decision trigger has not been reached.
3. When a trigger is reached, pause implementation, gather the named evidence, and ask the user if the choice materially affects product direction, cost, privacy, or lock-in.
4. On resolution, mark the row `Resolved`, record the result and date, and link the accepted architecture decision. Do not delete its history.
5. A package or SDK may not be installed merely because it is popular; it must own a declared boundary and satisfy the existing contract/replacement tests.

Statuses are `Open`, `Deferred`, `Evidence needed`, or `Resolved`.

The live adapter still needs structured-output, context-limit, privacy, latency, resource, offline, and replacement evidence. The durable globally shared AI journal remains deferred until integrated application/storage work can coordinate it with Phase 6.

Phase 8A resolves the desktop, microphone, STT, and local model implementation choices with the Electron production graph and records the remaining physical acceptance evidence. Default-deny permissions, Node-runtime-enforced filesystem/process/worker/add-on/WASI/heap restrictions, credential-shaped environment filtering, fail-closed unavailable providers, and deterministic inspectable packaging are implemented and proven. `SEC-001`, `NAT-001`, and `CNT-001` remain unresolved. The installed Node build exposes no network permission flag, so outbound network is **adapter-enforced, not Node-runtime-enforced**; a component that bypassed the model configuration boundary and used `node:net` directly would not be stopped by this host.
